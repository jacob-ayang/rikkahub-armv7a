# 首次 ARMv7a 真机验收

首次测试针对 Android 8.0 及以上、支持 ARMv7a 的设备。正式发布开关保持关闭，
测试 APK 位于 Actions 的 `armv7a-release-*` 附件和 3.1.1 Release 草稿中。
同一附件内的 `build-info.json` 记录 APK 的 SHA-256、签名证书和准确源码提交。

## 安装和数据

1. 在原 2.1.12 中导出一份备份，并保存在应用目录之外。
2. 直接安装测试 APK 覆盖旧版，保留应用数据。旧版 versionCode 为 155，新版为 194；
   CI 会核对新旧签名一致。如果系统提示签名冲突，请记录错误，不要通过清除数据绕过。
3. 打开原有会话，检查助手、模型配置、历史消息和附件。发送一条消息，确认聊天正常。
4. 搜索一段原有中文消息，再尝试拼音搜索；创建新会话后也应能搜索到新消息。
5. 验证备份导出、导入，并运行一项实际使用的 JavaScript 工具或脚本。

## 工作区和终端

1. 创建本地工作区，使用默认链接安装 **armhf** Linux 镜像。
2. 在终端运行 `uname -m`、`printf hello`、`pwd`，确认可以启动和执行命令。
   写入一个文件，关闭再打开终端，确认内容保留。
3. 在已有工作区中尝试安装 ARM64 镜像，应明确拒绝，原 armhf 文件不应被删除。
4. 有 SSH 测试环境时，验证连接、命令、交互终端和文件访问；没有该环境时请注明尚未真机验证。

## 反馈和开启自动发布

请反馈设备型号、Android 版本、APK 的 SHA-256，以及上述检查的通过情况或错误截图。
首次公开发布前，App 内更新入口可能提示没有可用的正式 ARMv7a 版本；它不应提供上游 ARM64 包。

验收通过后，将测试包 `build-info.json` 中的 `apk_sha256` 写入
`fork/config.json` 的 `device_validation.baseline_apk_sha256`，并将 `approved` 设为 `true`。
提交后运行 Sync Upstream，自动化会核验并公开这个已经测试的 APK。
以后的正式版经过 CI 检查后自动发布，不再逐次要求人工确认。
